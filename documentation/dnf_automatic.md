# dnf_automatic

Installs dnf-automatic and declares the host's baseline configuration. Declare it once per node; `base::packages`
does this on every OSL EL host. A second `dnf_automatic` with a different name fails the run. Other cookbooks
change the outcome with [`dnf_automatic_policy`](dnf_automatic_policy.md), not by declaring this again.

The package is installed when the resource converges. The merged configuration (this baseline plus every policy) is
applied once, at the end of the run, by the internal `dnf_automatic_apply` resource. If the converge failed before
reaching every resource, nothing is applied and the existing configuration stays, so a policy the run never got to
(a package hold, say) is not silently dropped. Otherwise:

- `/etc/dnf/automatic.conf` is rendered with every key the installed release understands, written out explicitly,
  because dnf-automatic's built-in defaults differ from its shipped file (for example, `random_sleep` is 300 in code).
- `dnf-automatic.timer` is enabled and started, or stopped and disabled when `enabled` ends up false.
- A `dnf-automatic.timer.d/osuosl.conf` drop-in carries `on_calendar` and `randomized_delay`. It is removed when both
  are unset, which returns the timer to the packaged 06:00 plus up to 60 minutes.
- `dnf-automatic-install.timer`, `dnf-automatic-download.timer` and `dnf-automatic-notifyonly.timer` are stopped and
  disabled. Their services pass flags that override `automatic.conf`, they would run alongside the main timer, and
  dnf5 no longer ships them.

## Actions

| Action | Description |
|---|---|
| `:configure` | Default. Installs the package and records the baseline. |

## Properties

| Property | Type | Default | Description |
|---|---|---|---|
| `apply_updates` | true, false | `true` | Install downloaded updates. |
| `download_updates` | true, false | `true` | Download available updates. `false` also turns off `apply_updates`. |
| `upgrade_type` | `default`, `security` | `default` | `security` limits updates to those with a security advisory. |
| `random_sleep` | Integer | `0` | Extra random delay in seconds before a timer run. |
| `network_online_timeout` | Integer | `60` | Seconds to wait for the network. |
| `reboot` | `never`, `when-changed`, `when-needed` | `never` | Reboot after applying updates; `when-needed` reboots only for kernel, glibc, systemd and similar. EL9+. |
| `reboot_command` | String | package default | Command used to reboot. Matching outer quotes are stripped by dnf. EL9+. |
| `emit_via` | Array of `stdio`, `email`, `motd`, `command`, `command_email` | `%w(stdio)` | Where results go. `motd` overwrites `/etc/motd`. |
| `system_name` | String | hostname | Name used in messages. |
| `send_error_messages` | true, false | `false` | Also emit when a run fails. EL9+. |
| `email_from` | String | `root@example.com` | Sender for the `email` emitter. |
| `email_to` | Array | `%w(root)` | Recipients for the `email` emitter. |
| `email_host` | String | `localhost` | SMTP server. |
| `email_port` | Integer | `25` | SMTP port. EL8 always uses 25. |
| `email_tls` | `no`, `yes`, `starttls` | `no` | SMTP TLS. EL10+. |
| `command_email_from` | String | `root@example.com` | Sender for the `command_email` emitter. |
| `command_email_to` | Array | `%w(root)` | Recipients for the `command_email` emitter. |
| `exclude` | Array | `[]` | Package globs dnf-automatic must not update. Rendered as `[base] exclude`, which adds to the excludes in `dnf.conf`. |
| `base_options` | Hash | `{ 'debuglevel' => 1 }` | Any other `dnf.conf` option to set for dnf-automatic runs only. |
| `header` | true, false | `true` | Put the "generated by" header in `automatic.conf`. |
| `on_calendar` | String | none | systemd `OnCalendar=` for `dnf-automatic.timer`, e.g. `*-*-* 10:10 US/Pacific`. |
| `randomized_delay` | String | none | systemd `RandomizedDelaySec=`, e.g. `15m`. |
| `enabled` | true, false | `true` | Run `dnf-automatic.timer` at all. |

## Release support

dnf-automatic silently ignores options it does not know and values it cannot parse, logging them at debug level
only. So options a release would ignore are left out of the file. If the merged value of one of them is not its
default, the run fails, naming the option and who set it, rather than leaving the host doing something nobody asked
for.

| Option | EL8 (dnf 4.7) | EL9 (dnf 4.14) | EL10 (dnf 4.20) |
|---|---|---|---|
| `reboot`, `reboot_command` | no | yes | yes |
| `send_error_messages` | no | yes | yes |
| `email_port` other than 25 | no | yes | yes |
| `email_tls` | no | no | yes |

dnf-automatic sends nothing when there are no updates, whatever the emitter.

## Examples

```ruby
dnf_automatic 'default' do
  emit_via %w(email)
  email_from 'root@example.org'
  email_to %w(dnf-automatic@example.org)
  command_email_from 'root@example.org'
  on_calendar '*-*-* 10:10 US/Pacific'
  randomized_delay '15m'
end
```

```ruby
# Packaged schedule, notify only, no header
dnf_automatic 'default' do
  apply_updates false
  download_updates false
  header false
end
```
